How I work

No theater. Just a tight loop from questions → evidence → decisions → UI.

  • 1) Define the problem What are we solving, for who, and how will we know it worked?
  • 2) Map the current reality Workflows, constraints, edge cases, and why users struggle.
  • 3) Research fast, learn faster Interviews, usability testing, surveys, competitive reviews—pick the method that answers the question.
  • 4) Prototype & validate Low → high fidelity depending on risk. Test early, fix cheap.
  • 5) Ship with a system Components, states, tokens, and documentation so the UI stays consistent after launch.
